# Zotero AI Assistant

给 Zotero 装上大脑：**摘要、翻译、图表解读、批判性分析、全文问答、文献库找 idea**——围绕科研人员「读懂 → 读透 → 联结」的真实工作流设计。

## 为什么写这个插件

Zotero 管好了文献，但**读文献的痛还在**：

- 英文论文读得慢，翻译软件切来切去
- PDF 太长，抓不住重点，读完就忘
- 一篇论文说完了什么，说不清道不明
- 几十篇文献之间什么关系，全靠脑子记

这个插件不试图替代阅读，而是**降低门槛、加深理解、建立联结**：

| 层面 | 解决什么 |
| --- | --- |
| 📖 **读懂** | 结构化摘要、选择性翻译、图表解读、批判性分析 |
| 🧠 **读透** | 基于全文的问答（带页码引用）、引导式提问 |
| 🗂️ **联结** | 跨文献对比矩阵、文献库找研究空白/冲突/相邻工作 |

## 功能一览

### ⚡ 一键生成

点一下，依次完成**摘要 + 标签 + 图表解读**。每步独立渲染，中途可停止。

### 📝 生成摘要

读取条目元数据 + PDF/EPUB 全文，输出五段式结构：

```
1. 研究问题与动机
2. 方法与数据
3. 主要发现
4. 结论、贡献与适用边界
5. 局限与未来工作
```

- 篇幅可调：简短（250–400 字）/ 标准（600–1000 字）/ 详细（1200–2000 字）
- 可保存为**子笔记**、写入**「摘要」字段**，或仅显示
- 流式输出，随时停止

### 🌐 选择性翻译

不只是标题和摘要——**想翻什么翻什么**：

- 勾选「标题」「摘要」，或粘贴任意段落
- 目标语言自动判断，也可强制指定
- 结果保存为子笔记，可选写入 `Extra` 字段

### 📊 图表解读

从文献中提取图表、表格、公式，让模型解释：

- 图表类型与主题
- 坐标轴 / 表头含义
- 趋势与对比关系
- 对论文结论的支撑作用
- 值得注意的细节（缺失基线、单位问题等）

> 说明：解读基于**结构化文本**（标题、表头、单元格）。纯图片内容需要多模态模型支持，本插件暂不涉及。

### 🔍 批判性分析

不做总结，专找漏洞：

- 研究设计与因果推断
- 样本与代表性
- 测量与指标（循环论证、代理变量偏差）
- 基线与对比是否公平
- 效应量 vs 统计显著性
- 可复现性
- 结论与证据的逻辑跳跃

### 💬 文献问答

在条目面板直接提问，AI 检索全文相关片段后回答：

- **页码引用**：`[p.4]` 可点击，跳转到阅读器对应页
- **多轮对话**：按条目持久化，重启 Zotero 后恢复
- **提示词模板**：论文精读 / 通俗讲解 / 对比辨析 / 复现指南 / 找漏洞
- 可编辑、可保存为自定义模板

### ✨ 找 idea

在**整个文献库**里检索，回答三种问题：

| 模式 | 用途 |
| --- | --- |
| 找研究空白 | 「被提到但没被解决」的问题 |
| 找结论冲突 | 结论互相矛盾的文献，分析差异来源 |
| 找相邻工作 | 以某篇文献为种子，找可借鉴的相邻研究 |

检索基于 Zotero 的全文索引（SQLite FTS5），速度快且覆盖正文。

### 🗂️ 跨文献矩阵

选中多篇文献 → 生成对比表：

| 标题 | 年份 | 方法 | 数据集/样本 | 核心发现 | 指标 | 基线 | 局限 | 代码数据 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |

### 🗂️ 单篇笔记聚合

一篇论文的所有 AI 输出写进**同一个**「AI 助手」笔记，按类型分节：

```
AI 助手
├── 摘要（2026/10/28 16:54 · 由 DeepSeek 生成）
├── 图表解读（2026/10/28 17:02）
├── 批判性分析（2026/10/28 17:05）
└── 翻译（中文）· 标题+摘要（2026/10/28 17:10）
```

同名小节自动覆盖，不会越点越乱。

## 快速开始

### 1. 安装

从 [Releases](../../releases) 下载 `.xpi`，然后：

**Zotero → 工具 → 插件 → 齿轮图标 → Install Add-on From File… → 选择 xpi → 重启**

### 2. 配置模型

**Zotero → 编辑 → 设置 → AI 助手**

1. **模型配置**下拉框选一个预设（OpenAI / DeepSeek / 火山方舟…）
2. 填 **API Key**
3. 确认**接口地址**（预设通常已填好）
4. 点 **测试连接**，成功后再继续

### 3. 开始使用

选中任意文献 → 右侧面板出现「**AI 助手**」：

```
阅读与理解
[⚡ 一键生成] [📝 摘要] [🌐 翻译] [🏷️ 标签] [📊 图表]

分析与发现
[🔍 批判] [✨ 找 idea]
──────────────────────────────
[↻ 重新生成] [📂 打开笔记] [清空]
──────────────────────────────
[ 模型选择 ▼ ]  当前配置 · 地址

[ 输入问题…                          ] [发送]
```

**最直接的体验**：点 **⚡ 一键生成**，等着看结果。

## 配置模型

### 内置预设

| 服务商 | 说明 |
| --- | --- |
| OpenAI | GPT-4o / 4.1 系列 |
| Anthropic Claude | Claude Messages API（独立协议） |
| DeepSeek | 国内直连，性价比高 |
| 通义千问 Qwen | 阿里云百炼 |
| 智谱 GLM | BigModel |
| Kimi / Moonshot | 长上下文 |
| 硅基流动 | 一个 key 用多家模型 |
| 火山方舟 Ark | Coding Plan 专用地址 |
| Ollama | 本地模型，无需 Key |

### 多配置切换

每个配置是完整独立的一套（名称 / 协议 / Key / 地址 / 模型）：

- **新增** —— 创建空白配置
- **复制** —— 基于当前配置克隆
- **删除** —— 删除自定义配置（内置不可删）

条目面板顶部的**模型下拉框**可快速切换，不用进设置。

### 模型列表管理

```
模型
[ 选择模型 ▼ ]  [设为当前模型]

[获取模型列表] [添加模型] [清空全部] [测试全部]
```

- **获取模型列表** —— 调 `GET /models` 拉取，候选存入本地
- **添加模型** —— 加入候选列表里的一个真实模型
- **测试全部** —— 并发测试所有已添加的模型，逐行标 ✓ / ✗
- 模型 ID 是**可搜索下拉框**，输入即过滤

> **务必从下拉框选模型，不要手输。** 服务商的模型名带版本号或日期后缀，手输极易出错。

### 火山方舟注意事项

```
协议：OpenAI 兼容 (/chat/completions)
地址：https://ark.cn-beijing.volces.com/api/coding/v3
模型：doubao-seed-2.0-pro-260215   ← 带日期后缀
```

- Coding Plan 用 `/api/coding/v3`，**不要用 `/api/v3`**（控制台明确警告会产生额外费用）
- 模型名**必须带日期后缀**（如 `-260215`）
- 控制台的「Auto」是 UI 选项，API 不认，请选具体模型

## 常见问题

### 连接失败：模型名称不被识别

**从下拉框选，不要手输。** 常见错误：

| 错误写法 | 正确写法 |
| --- | --- |
| `doubao-lite-4k` | `doubao-seed-2.1-lite` |
| `deepseek-v4-1-flash` | `deepseek-v4.1-flash` |
| `gpt-4o`（在火山） | `doubao-seed-2.0-pro-260215` |

### 连接失败：该模型未开通

到服务商控制台开通对应模型。火山方舟需要在 Coding Plan 页面选中模型并等 3–5 分钟生效。

### 摘要/回答是空的

推理模型（DeepSeek-R1、o 系列）会先消耗 token 做思考。**调高「最大 tokens」**（建议 8192 以上）。

### 图表解读说「未提取到」

可能原因：文献是扫描版、图表是纯图片、或尚未建立全文索引。Zotero 打开 PDF 时会自动索引，稍等再试。

### 页码引用没有出现

页码来自 Zotero 的结构化文档数据（SDT 包）。文献需要先被索引，且模型需在回答中标注 `[p.X]`。

### API Key 安全吗？

Key 只存在本机 Zotero 配置（`prefs.js`）中，**不会上传到任何地方**。请求直接发往你配置的服务商。

## 隐私与安全

- **数据流向**：文献元数据 + 正文 → 你配置的服务商 API
- **本地存储**：API Key、模型列表、对话记录 → Zotero `prefs.js`
- **无中间服务器**：插件不经过任何第三方服务

> 请注意：使用本插件意味着**将文献内容发送到所选服务商**。涉密文献请谨慎，或使用本地 Ollama。

## 技术架构

```
src/
├── ai/
│   ├── providers.ts      服务商预设 + 多配置管理
│   ├── client.ts         OpenAI / Claude 双协议请求，SSE 流式
│   ├── prompts.ts        提示词与解析
│   ├── analysis.ts       图表 / 批判 / 矩阵 / 找 idea 提示词
│   ├── features.ts       高层功能编排
│   ├── tokens.ts         上下文预算与历史裁剪
│   └── modelTest.ts      批量模型可用性测试
├── services/
│   ├── sdt.ts            Zotero 结构化文档包解码（页码引用）
│   ├── itemText.ts       全文提取 + 分块检索
│   ├── notebook.ts       单篇笔记聚合（结构化存储 + 重建）
│   ├── librarySearch.ts  文献库全文检索（FTS5）
│   └── modelRegistry.ts  模型列表与候选缓存
├── modules/
│   ├── ui.ts             条目面板（问答 / 流式 / 页码链接）
│   ├── askDialog.ts      提问对话框（提示词模板）
│   ├── translateDialog.ts 选择性翻译对话框
│   ├── ideaDialog.ts     找 idea 对话框
│   └── preferenceScript.ts 设置面板
└── utils/                prefs / locale / ztoolkit
```

### 兼容性

| 项目 | 说明 |
| --- | --- |
| Zotero | 7 / 8 / 9 / 10（`strict_max_version 10.*`） |
| 运行环境 | Firefox 140 ESR 内核（Zotero 10） |
| 面板 API | `ItemPaneManager` / `MenuManager`（Zotero 8+，Zotero 7 自动降级） |
| 全文 | `PDFWorker.getFullText` + SDT 包 |
| 检索 | `Zotero.Search` + `fulltextContent`（FTS5） |

## 参与开发

### 环境

- Node.js ≥ 22.8
- Zotero 7+（用于测试）

### 构建

```bash
npm install

# 配置 Zotero 路径（复制并修改）
cp .env.example .env

npm start        # 开发模式：启动 Zotero 热重载
npm run build    # 生产构建，输出 .scaffold/build/*.xpi
npm test         # 在真实 Zotero 中运行测试
```

### 测试

测试在**真实 Zotero 实例**中运行，覆盖：

| 领域 | 内容 |
| --- | --- |
| 启动 | 插件加载、面板 / 菜单 / 设置注册 |
| 提示词 | 标签解析、翻译解析、页码引用、名称推导 |
| SDT | 包解码、页码提取、分块 |
| 模型 | 列表增删、重命名去重、显示名 |
| 配置 | 多配置增删改、内置预设覆盖持久化 |
| 本地化 | 字符串解析（防止出现原始 ID） |

### 提交 PR

1. Fork 本仓库
2. 新建分支，提交改动
3. 确保 `npm run build` 与 `npm test` 通过
4. 描述清楚**解决了什么问题**、**如何验证**
